# Level 4：基于 U-Net 的手写笔记擦除

输入一张带手写答案 / 批注 / 演算的试卷图片，输出一张**保留印刷文字、表格和题目结构、
擦除全部手写内容**的干净图片。

```
INPUT (拍摄 + 手写)          PRED (擦除后)              GT (干净版)
┌──────────────────┐        ┌──────────────────┐      ┌──────────────────┐
│ 1. 求 x 的值      │        │ 1. 求 x 的值      │      │ 1. 求 x 的值      │
│   x = 3  ←手写    │  ───>  │                  │  ≈   │                  │
│ ▓▓▓▓▓▓▓▓ 表格线   │        │ ▓▓▓▓▓▓▓▓ 表格线   │      │ ▓▓▓▓▓▓▓▓ 表格线   │
│   5 ✗ ←红笔批改   │        │                  │      │                  │
└──────────────────┘        └──────────────────┘      └──────────────────┘
```

## 快速开始

```bash
pip install -r requirements.txt

# 1) 数据清洗 + 划分（已执行：2412 对 -> 2140 对，1712/214/214）
python data.py --root data/deli --out splits.json --downscale 2
python data.py --root data/deli --list          # 只看目录结构

# 2) 小数据快速验证流程（约 0.5 分钟，< 0.05 元）
python train.py --splits splits.json --limit_train 64 --max_steps 100 \
                --eval_every 20 --patch 192 --tag quick

# 3) 正式训练（本次实际使用，62 分钟 / 2.08 元）
python train.py --splits splits.json --max_steps 20000 --eval_every 20 \
                --batch_size 8 --patch 256 --base_ch 48 --mask_weight 5.0 \
                --amp bf16 --tag final20k

# 4) 推理 + 指标 + 可视化对比（三联图存到 pred/compare/）
python inference.py --ckpt runs/<时间戳>-final20k/best.pth \
                    --splits splits.json --split test --output pred --limit 40

# 5) 改了绘图样式但不想重训时，直接从 log.csv 重绘曲线
python train.py --replot runs/<时间戳>-final20k
```

单卡显存占用 3.04 GB（8.5 GB 的 RTX 5060 Laptop 可跑），每步 0.158 s。

**仍存在的失效模式**（看图能直接看到，不建议只看指标）：
1. 手写擦除后会留下**淡灰色印子**——回归损失的条件均值解，这是生成式方法（GAN/Diffusion）要解决的问题
2. 光照归一化偏激进，会把页面浅色细线（卡通插画、装饰图标）一起冲淡，
   对应上表 2 张 `INK_LOST` 与墨迹保留率 0.828（未到 1.0）

### 后续实验：ghost20k（2026-09-26，断点续训跑完）

针对失效模式 1 加了**灰印子损失项**（掩码内"残留笔画状暗结构"的 L1，`--w_ghost 2.0`），
其余配置与 final20k 完全相同（UNet base=48，20000 步 / 68 min / 2.27 元）。测试集 40 张同口径对比：

| 模型 | 手写区误差 | 非手写区误差 | 灰印残留 | PSNR | 墨迹保留率 |
|---|---|---|---|---|---|
| final20k | 0.165 | 0.042 | 57.1% | 20.65 dB | 0.828 |
| ghost20k（best，按 PSNR 选） | **0.063（−62%）** | 0.054 | **20.2%** | 19.37 dB | 0.561 |
| ghost20k（best_ink，按手写区误差选） | **0.053（−68%）** | 0.065 | **15.8%** | 18.24 dB | 0.462 |

**结论：方向对、剂量过头**。灰印子失效模式被基本解决（残留 57%→16~20%），
但 `w_ghost=2.0` 学到的"把细暗笔画推向 0"泛化到了掩码外的印刷细线上——
非手写区误差 +30%，墨迹保留率掉到 0.5 左右，16/40 张触发 `INK_LOST`。
500~2000 步扫描时"非手写区误差会随步数收敛"的假设被全量训练证伪。
下一步：`w_ghost` 降到 0.5~1.0、或 ghost 权重后期退火。产物：
`runs/20260916-194652-ghost20k/`、`pred_ghost*/`。

### 后续实验：dit20k（2026-09-26，18000 步停止）

用 DiT（dim=384, blocks=8, 14.6 M）+ 相同 `w_ghost=2.0` 验证"过度擦除是 ghost 项的
固有属性、与骨干无关"。测试集 40 张同口径（final20k / ghost20k 一并复算，逐项吻合）：

| 模型 | 手写区误差 | 非手写区误差 | 灰印残留 | PSNR | 墨迹保留率 |
|---|---|---|---|---|---|
| final20k（UNet 基线） | 0.165 | 0.042 | 57.1% | 20.65 dB | 0.828 |
| ghost20k best（UNet） | **0.063** | **0.054** | **20.2%** | **19.37 dB** | 0.561 |
| dit20k best | 0.121 | 0.074 | 28.3% | 18.69 dB | 0.745 |
| dit20k best_ink | 0.105 | 0.081 | 21.3% | 17.91 dB | 0.578 |

**结论**：① 过度擦除与骨干无关——DiT 同样把非手写区误差推高近一倍；② 同尺度下 DiT
每步 808 ms（U-Net 158 ms，5 倍耗时）却全面更差，**256px 任务上 Transformer 路线关闭**；
ghost 修正只在 U-Net 上继续（w_ghost 降到 0.5~1.0 或后期退火）。产物：
`runs/20260925-220630-dit20k/`、`pred_dit*/`。

## 数据集实际情况（重要）

解压后结构：

```
data/deli/2025021{1,2,3}/dataset/input/*.jpg    拍摄的试卷（有手写、有阴影、有透视）
data/deli/2025021{1,2,3}/dataset/output/*.jpg   清理后的同一页（无手写、亮度归一）
```

实地核查得到的三个结论，直接决定了训练策略：

1. **几何是对齐的**：用 ECC 在 20 对随机样本上估计平移残差，中位数为 **0~2.6 px**。
   所以可以直接做像素级回归，不需要先做单应配准。
2. **主要差异是"光度归一 + 手写擦除"**：`input` 是手机拍摄（灰度均值 ~171，有明显阴影带），
   `output` 是平面的清理版（灰度均值 ~237）。90% 以上像素差异 > 40 灰度级，
   但这是亮度归一化贡献的，不是几何错位。
3. **墨迹量显著下降**：典型样本 `input` 墨迹像素占比 10.3% → `output` 2.5%。

因此本任务的完整目标 = **去阴影/亮度归一 + 去噪声/模糊 + 擦除手写**，
三者都要学。这也意味着 PSNR/SSIM 里有一部分分数来自光度归一化，
不能单独用它衡量"手写擦得干不干净"——所以另外报告**墨迹保留率**和**擦除率**（见下文）。

4. **数据成分不纯**：抽样发现混有**非试卷类文档**（机动车登记证书等表单）、
   卡通插画、以及若干近空白页。说明 `output` 是自动化流程批量生成的、并未逐张人工校验。
   清洗能剔除空白页与重复页，但语义异常样本会残留，构成本任务的指标上限。

### 误差分解：指标好看 ≠ 任务做对了

用"标定过的"手写掩码把预测误差拆开（17 张测试图）：

| 模型 | 手写区误差 | 非手写区误差 |
|---|---|---|
| 第一版：`\|in−gt\|` 掩码、w=0.5、4000 步 | **0.387** | 0.035 |
| 最终：局部对比度掩码、w=5.0、20000 步 | **0.157** | 0.043 |

第一版整体 PSNR 已有 10 → 19 dB 的提升、擦除率 0.81，
**但手写区域的误差只降到 0.387 —— 笔迹基本还在**。
提升几乎全部来自阴影/亮度归一化（它占了 90% 以上的像素差异）。

这不是指标算错了，而是**任务本身不均衡**：光度归一化贡献了约 71% 的损失，
手写擦除只占 29%。回归损失自然会先优化前者。
诊断出这一点之后才有了下面"代理掩码"那条修正，手写区误差最终降了 **59%**
（代价是非手写区误差从 0.035 微升到 0.043，即擦除更激进了一些）。

### 清洗结果

```
[扫描] data\deli  布局=dir(input/output)  配对=2412
[清洗] 2412 对 -> 保留 2140 对 (88.7%)
       丢弃: 过小=154  极端长宽比=16  GT空白=10  重复=89  GT无墨迹=1  输入空白=1  尺寸不符=1
[划分] train=1712  val=214  test=214
```

清洗规则（`data.py: clean_pairs`）：

| 规则 | 阈值 | 为什么必须做 |
|---|---|---|
| 可解码 | — | 网盘下载存在损坏文件 |
| 最小边 | ≥ 96 px | 太小的条带图无法提供有效 patch |
| 长宽比 | ≤ 8.0 | 排除细长截图碎片 |
| 输入非空白 | 灰度 std ≥ 4.0 | 全白输入没有可学的擦除信号 |
| **GT 非空白** | 灰度 std ≥ 4.0 | GT 若是白纸，等于教网络"清空整页"→ 直接导致验收失败项"输出全白" |
| **GT 有墨迹** | 黑像素占比 ≥ 0.2% | 同上，GT 必须保留印刷内容 |
| 配对比例一致 | 长宽比差 ≤ 0.06 | 保证像素级对应 |
| 查重 | 64-bit dHash 汉明距离 ≤ 2 | 剔除重复页（实际删掉 89 对） |

### 标注规范（人工抽检用）

本任务**不需要逐像素 mask 标注**，只需保证配对正确 + GT 确实干净。

**必须擦除**：学生作答笔迹、演算草稿、涂改、老师批注（对勾/叉/圈/分数/评语/红笔划线）、
学生标记（下划线/圈画/箭头）、铅笔淡痕。

**必须保留**：印刷题干与选项、印刷公式、表格线与答题框、页眉页脚页码、条形码二维码、
印刷 Logo/水印、答题卡的**空白填涂框**（框保留，框内涂黑算手写）。

**边界规则**：
- 手写压在印刷字上 → 擦除手写，被完全遮挡的印刷笔画允许缺失，**不允许凭空生成内容**（防幻觉）
- 干净图自带的褶皱、污渍、装订阴影 → 保留，网络只该学擦手写，不该顺手美化
- 手写极淡（浅灰） → 以人眼能否辨识为准，能辨识就擦

**质量验收（抽检 100 张）**：配对错误率 < 1%；GT 手写残留率 < 2%；
明显配准偏差（> 5 px）率 < 2%。

本数据集实测已发现少量**语义异常样本**（例如混入了一张卡通插画、若干近空白页），
这说明 `output` 是自动化流程生成的、并非全部人工校验过。清洗能剔除其中一部分，
但剩下的只能靠"难例挖掘"人工复查。

### 划分策略

**按页面分组划分**（`split_pairs`），不按图片划分——同一页面的不同裁剪块必须整体
落入同一集合，否则验证指标会被严重高估。比例 8:1:1，固定种子 3407，
结果落盘为 `splits.json`。

## 文档图像增强（`data.py: DocAugment`）

原则：**几何变换对 (输入, GT) 同步施加；光度退化只作用于输入。**

| 类别 | 变换 | 参数 |
|---|---|---|
| 几何（同步） | 旋转 | ±2.5° |
| 几何（同步） | 缩放 | 0.92 ~ 1.08 |
| 几何（同步） | 透视扰动 | ≤ 1.2% 短边 |
| 几何（同步） | 平移 | ±2% |
| 光度（仅输入） | 光照不均 / 纸张阴影 | 乘性低频场 0.76~1.06 |
| 光度（仅输入） | 亮度 / 对比度 | ±0.20 |
| 光度（仅输入） | 伽马（曝光 / 墨迹浓淡） | 0.65 ~ 1.5 |
| 光度（仅输入） | 高斯 / 运动模糊 | 核 3~7，概率 0.35 |
| 光度（仅输入） | 传感器噪声 | σ ≤ 0.035 |
| 光度（仅输入） | JPEG 压缩伪影 | 质量 35~90，概率 0.35 |

**手写区域偏置采样**：60% 概率按 `|输入 − GT|` 差异图（模糊 + 积分图加速）作为概率图
选择裁剪位置，避免大量纯空白 patch 浪费算力。

## 模型与损失

### U-Net + 残差学习（`model.py: UNet`）

网络预测的不是干净图本身，而是**需要擦掉的内容**：

```python
out = clamp(input - residual_pred, 0, 1)
```

擦除任务里被改动的像素只占少数，学残差比从零重建整页收敛更快、印刷体保真度更高。
其它设计：GroupNorm（小 batch 稳、推理行为一致）；任意尺寸输入（自动 pad 到 2^depth 倍数）；
可选 Attention Gate（`--attn`），在 skip connection 上门控以抑制手写特征传播。

### 组合损失（`model.py: RestorationLoss`）

```
L = 1.0·L1 + 0.2·(1−SSIM) + 0.2·Edge      (+ 可选 0.0·MSE)
```

| 损失 | 作用 | 单独用的缺陷 |
|---|---|---|
| MSE | 对大误差敏感、优化稳定 | 产生"平均化"的模糊结果，细笔画被抹平 |
| L1 | 对离群点鲁棒、边缘锐利 | 梯度恒定，平坦区后期震荡 |
| SSIM | 直接优化结构相似度，保住笔画结构 | 对亮度/颜色偏移不敏感 |
| Edge | Sobel 梯度域 L1，护表格线与字符轮廓 | 单独用会放大噪声 |

自实现的 SSIM 与 `skimage.metrics.structural_similarity(gaussian_weights=True)` **逐位对齐**
（误差 3e-07），保证训练曲线与推理评测口径一致。

### 另一个隐蔽的坑：bf16 下 SSIM 会算错

在 `--amp bf16` 下，SSIM 损失会出现**负值**（日志里是 `-0.445`）。
排查发现这不是训练问题而是数值问题：SSIM 的局部方差是 `E[x²] − μ²` 相减得到的，
而文档图是大面积近白底、局部方差极小，**bf16 的 8 位尾数在这种相减里完全失效**。

实测同一份输入：

| | fp32 | bf16 autocast |
|---|---|---|
| `1 − SSIM` | 0.2115 | **0.4375**（误差 2 倍，还会出负值） |

日志里 `ssim_loss=0.30078125`（=77/256）、`edge=0.62109375`（=159/256）
这些恰好是 1/256 整倍数的值，就是 bf16 量化的指纹。

修复：`RestorationLoss` 与 `ssim()` 内部显式 `torch.autocast(..., enabled=False)`
并转 `float32`，整个损失都在 fp32 下计算（`model.py`）。
修复后 autocast 与 fp32 的差异降到 8e-06，并加了自检断言防回归。
**这个 bug 不修，模型会一直朝着一个坏掉的 SSIM 信号优化。**

**手写区域加权**（`--mask_weight`，默认 5.0）：本任务没有像素级标注，
需要构造代理掩码给 L1 加权：`L1 = Σ(w ⊙ |ŷ−y|) / Σw`，其中 `w = 1 + λ·mask`。

**这里有一个不显然但影响巨大的坑**：直觉上应该用 `|输入 − GT|` 的差异图当掩码，
但本数据集的输入是拍摄图，**大面积阴影造成的灰度差异比笔迹还大**——
实测这样得到的掩码覆盖了 **95.5% 的像素**，权重图几乎均匀，等于完全没加权。

正确做法是用**局部对比度**区分笔画和阴影（`model.py: proxy_mask`）：

```python
bg = avg_pool2d(gray(inp), 31)          # 局部背景亮度
mask = (bg - gray(inp) > 0.12) & (gray(gt) > 0.60)
#      ↑ 比邻域明显更暗 = 细笔画      ↑ GT 处是白底 = 没有印刷内容
```

阴影是**低频**的（邻域均值与自身接近，`bg − g ≈ 0`），笔迹是**高频**的，两者可以分开。
新掩码覆盖率降到 **1.0%**，精准落在手写笔迹上。
效果：用新掩码训练 **500 步**的手写区误差（0.342）就已经优于旧掩码训练 **4000 步**（0.384）。

局限：`gt > 0.60` 这一条会排除"写在印刷文字/表格线上的手写"——
那部分只能靠基础 L1 覆盖，是当前结构的主要失效场景。

### 关于"全白 / 全黑"检测的一个要点

干净试卷本身就是**大面积白底**（实测 GT 灰度均值 ≈ 0.93），
所以"白色像素多"绝不能判异常——那样会把所有正常输出都误报。
`blank_report()` 实际检测的是**退化**：

| 标记 | 判据 | 含义 |
|---|---|---|
| `BLANK_WHITE` | mean > 0.985 且 std < 0.02 | 整页纯白，印刷体也被擦没了 |
| `BLANK_BLACK` | mean < 0.03 且 std < 0.02 | 输出崩坏 |
| `LOW_CONTRAST` | std < 0.02 | 内容被抹平 |
| `INK_LOST` | 墨迹保留率 < 0.5（相对 GT） | 丢失印刷文字 / 表格线 |

另外报告两个可解释指标：
- **墨迹保留率** = 输出墨迹像素占比 / GT 墨迹像素占比，1.0 = 印刷体完整保留
- **擦除率** = `1 − mean|输出−GT| / mean|输入−GT|`，1.0 = 输入与 GT 的差异被完全消除

## 成本控制

预算 30 元。控制手段：

1. **两阶段验证**：先 `--limit_train 64 --max_steps 100` 跑通流程（0.5 分钟、< 0.05 元），
   确认无误再正式训练
2. **按 step 而非 epoch 训练**，预算可精确控制（`--max_steps`）
3. **自动记账**：每次评估都刷新 `cost.json`，训练中断也不丢数据
4. **断点续训**：`--resume runs/*/last.pth` 直接写回原 run 目录——
   log.csv / curves.png 无缝续写，费用接着旧账累计，best_ink 状态也会恢复
5. **验证子集固定且只解码一次**并常驻内存（`--eval_images`），评估开销可忽略
6. **手写偏置采样**：减少无效空白 patch，等效提高每个 step 的信息量
7. **数据管线是真正的瓶颈**：实测单步里模型前向只占 0.05 s，而大图解码 + 增强占了
   0.3 s 以上。两个优化把每步从 0.36 s 降到 0.05 s：
   - 用 `cv2.IMREAD_REDUCED_COLOR_2` 让 JPEG 在 DCT 域直接缩放解码（`--downscale 2`）
   - 缓存解码结果与手写密度图，多 worker 并行（`--num_workers 4`）
   这一步省下的时间按 2 元/小时折算，等效于把预算翻了 7 倍

费用按 `--price_per_hour`（默认 2.0 元/小时，4090 租用参考价）折算，训练结束打印总账。

## 改进方案：从 U-Net 回归到 GAN / Diffusion

### 当前结构的天花板

| 现象 | 根因 |
|---|---|
| 细笔画（铅笔、细红笔）擦不干净，留灰影 | L1/SSIM 是均值型损失，惩罚权重正比于像素占比，而手写通常只占 2%~8% 像素 |
| 擦除处印刷笔画发虚、表格线断裂 | 回归损失的贝叶斯最优解是条件均值；手写与印刷重叠、信息缺失时输出折中的灰色 |
| 纸张纹理被抹平 | SSIM/MSE 偏好低频平滑解 |
| PSNR 高但人眼别扭 | PSNR/SSIM 与感知质量在生成式任务上相关性很弱 |

### A. 条件 GAN（PatchGAN）—— 感知质量性价比最高

```
输入 x ──> U-Net 生成器 G ──> ŷ
                (x, ŷ) ──> PatchGAN D ──> 真/假（逐 patch）
                (x, y) ──> PatchGAN D ──> 真
L_G = L_reg(ŷ,y) + λ_adv · L_adv(G)      L_D = 0.5·(BCE(D(x,y),1) + BCE(D(x,ŷ.detach()),0))
```

- 判别器用 **70×70 PatchGAN**（感受野覆盖一个文字块），比全局判别器更适合文档图
- **λ_adv 必须小**：`0.01 ~ 0.05`。重点是"擦干净且不破坏印刷体"，不是"生成以假乱真的内容"；
  λ_adv 过大会引入棋盘伪影和随机纹理
- 用 **LSGAN** 或 **hinge loss** 替代 BCE，训练更稳

稳定性措施（缺一不可）：判别器加 SpectralNorm；D 的学习率取 G 的 0.5 倍；
**延迟引入**（前 20% steps 只训回归，之后再开对抗）；D 输入加衰减高斯噪声；
监控 `L_D → 0`（说明 D 碾压 G，要降 D 学习率）。

预期：**PSNR 可能下降 0.2~0.8 dB（正常现象）**，LPIPS 明显改善，笔画边缘锐利、无灰影。
代价：显存 +10~15%，时间 +25~40%。必须与 baseline 并列汇报。
由于本项目 GT 是"清理版"，判别器还要同时判断"光度是否归一干净"，任务比纯擦除更难，
建议先只对**墨迹区域**做对抗（用代理掩码限定 D 的感受野）。

### B. Diffusion —— 质量上限最高，但要选对用法

从零训 DDPM 在 30 元预算内不可行（小图也需数百 GPU·小时）。三条可行路径：

| 路径 | 说明 | 训练成本 | 推理 | 幻觉风险 |
|---|---|---|---|---|
| B1 零样本 inpainting | 用 U-Net 输出或笔画检测器得到手写 mask，送入 SD-Inpainting，只在 mask 内采样 | 0 | 2~4 s/张 | **高** |
| B2 LoRA 微调 SD-Inpainting | rank 16 只训 attention，512px batch 4 约 1.5 s/step，2000 步 ≈ 1.7 元 | ~2 元 | 2~4 s/张 | 中 |
| B3 回归打底 + 扩散精修 | 现有 U-Net 输出 coarse，再用 4~8 步蒸馏采样的小扩散做残差精修 | ~3~5 元 | 0.3 s/张 | 低 |

- **B1 的幻觉风险对文档任务不可接受**：扩散模型可能凭空造出印刷字。
  必须限制采样步数（DDIM ≤ 20 步）、低 guidance（1.5~3），并在 mask 外强制覆盖原图像素
- **B2 是预算内首选**，效果通常显著优于零样本
- **B3 工程上最稳**：精修网络只学"边缘锐化 + 纹理恢复"，任务简单、幻觉可控

### C. 更好的监督信号（**性价比最高，优先做**）

1. **手写掩码监督**：现在用的是代理掩码。训练一个轻量笔画检测器（颜色 + 笔画宽度先验），
   即可在无 GT 的推理阶段给出 mask，实现双分支 `ŷ = m⊙clean + (1−m)⊙x` —— 
   **mask 外的像素完全不动**，彻底消除对非手写区域的影响，且输出可解释、可编辑
2. **Perceptual / LPIPS loss**（权重 0.05~0.1）：专门治"结构发虚"。
   注意 VGG 是 ImageNet 自然图像预训练的，对黑白文档不是最优，可换用文档预训练的 OCR 特征
3. **OCR-aware loss**：用冻结的 PP-OCR / TrOCR 提取特征或 CTC 输出做一致性约束。
   直接对齐下游任务，且顺带给出一个比 PSNR 更可信的指标：**擦除后的 OCR 准确率**
4. **频域损失** `|| |FFT(ŷ)| − |FFT(y)| ||₁`（权重 ~0.05）：抑制 GAN 常见的棋盘伪影
5. **多尺度监督**：在解码器 1/2、1/4 分辨率输出上各接 1×1 卷积做 GT 监督（权重 0.5/0.25），
   加速收敛 20%~30% ——**在固定预算下直接等于省钱**

### D. 结构改进

| 方案 | 参数 | 训练成本 | 预期 |
|---|---|---|---|
| Attention Gate（已实现，`--attn`） | +2% | +5% | 小幅提升 |
| 双流 mask + 重建 | +50% | +50% | 可解释、可编辑，擦除更彻底 |
| NAFNet | 17 M | 3× | 去噪 SOTA，明显优于 U-Net |
| Restormer | 26 M | 4× | Transformer 长程依赖，对整页版式理解更好 |

预算有限时优先顺序：**多尺度监督 > Attention Gate > 双流 mask > NAFNet**。

#### 关于放大模型与 Transformer（DiT）的实测结论

本项目的 GPU 是 RTX 5060 Laptop（8.5 GB）。实测各配置的显存与速度（patch 256）：

| 配置 | 参数量 | 峰值显存 | 每步耗时 |
|---|---|---|---|
| U-Net base=48（基线，batch 8） | 17.7 M | 3.04 GB | 158 ms |
| U-Net base=64（batch 8） | 31.4 M | 4.18 GB | 214 ms |
| **U-Net base=96（batch 8）** | **70.6 M** | **6.67 GB** | **402 ms** |
| U-Net base=128（batch 4） | 125.5 M | 5.86 GB | 322 ms |
| DiT dim=256, 6 blocks（batch 8） | 6.1 M | 3.42 GB | 488 ms |
| DiT dim=384, 8 blocks（batch 8） | 16.2 M | 5.49 GB | **808 ms** |

**反直觉的地方**：在 256px 这个尺度上，Transformer 并不划算。
16.2 M 参数的 DiT 要 808 ms/步，而 **70.6 M** 参数的 U-Net 只要 402 ms/步。
原因是 /4 分辨率下 4096 个 token 的全局自注意力是平方开销，
而卷积 U-Net 的参数量涨得快、计算量涨得慢。所以：

- **想用满显存换质量，优先加大 U-Net 的 `--base_ch`**，而不是换 Transformer
- Transformer 的价值在**更大感受野/整页版式理解**，要发挥它需要
  更大 patch（512+）或窗口化注意力（Swin/Restormer 的做法），
  而那时显存又不够了——8 GB 卡上这两条路互相冲突
- 本仓库已实现 `--arch dit`（`DiTRestore`，DiT 风格但直接回归不做扩散采样）
  供对比实验，但没有实现真·扩散 DiT：从零训扩散模型在 30 元预算内不可能，
  可行的扩散路线是 SD-Inpainting + LoRA 微调（见上节 B2）

### E. 数据侧（往往收益最大）

1. **针对本数据集的特殊问题**：GT 由自动化流程生成、质量不均（已发现混入插画、近空白页）。
   建议按"输入墨迹占比 − GT 墨迹占比"排序，人工复查两端异常样本，
   或训练一个 GT 质量判别器自动过滤
2. **难例挖掘**：记录 val PSNR 最差的样本人工检查，通常是"黑色手写压在印刷体上"，
   针对性合成补进训练集
3. **程序化合成配对**：干净母版 + 真实手写笔画素材（CASIA-HWDB 中文 / IAM 英文）+ 真实退化模型
4. **按来源分层划分**：本数据集有 3 个日期目录，测试集应覆盖全部三个，才能反映跨批次泛化

### F. 评价体系必须补充的指标

只用 PSNR/SSIM 会得出错误结论（它们奖励平滑解）。建议补：

| 指标 | 衡量什么 | 状态 |
|---|---|---|
| 墨迹保留率 | 印刷文字是否被误擦 | 已实现 `ink_keep` |
| 擦除率 | 输入与 GT 的差异被消除了多少 | 已实现 `removed_frac` |
| 手写残留率 | 还有多少手写没擦掉 | 需笔画检测器或人工 |
| OCR 准确率（CER） | 擦除后文字能否被正确识别 | 需接 PP-OCR |
| LPIPS | 感知质量 | 需 `lpips` 包 |
| 人工评分 | 最终裁决 | 5 人 × 50 张，1~5 分 |

### G. 结合 30 元预算的分阶段计划

| 阶段 | 内容 | 预估 | 累计 |
|---|---|---|---|
| P0 | 数据管线 + U-Net baseline 跑通 | < 0.5 元 | 0.5 |
| P1 | 超参搜索（用 200~500 步小规模试验选 patch/lr/loss 权重） | ~3 元 | 3.5 |
| P2 | 加多尺度监督 + 掩码加权 + LPIPS，做 loss 消融 | ~5 元 | 8.5 |
| P3 | 正式训练 4000~8000 步 + 完整评测（PSNR/SSIM/OCR/人工） | ~8 元 | 16.5 |
| P4 | 加 PatchGAN 对比实验 | ~6 元 | 22.5 |
| P5 | SD-Inpainting 零样本 PoC（不训练，只推理） | ~2 元 | 24.5 |
| P6 | 若 P5 可行 → LoRA 微调 | ~5 元 | 29.5 |

**一句话结论**：短期做「多尺度监督 + 手写掩码加权 + LPIPS + OCR 指标」，改的是监督信号
与评价体系，收益/成本比最高；中期加 PatchGAN 换取边缘锐利度（PSNR 会略降，需并列汇报）；
长期走 **SD-Inpainting LoRA 微调** 或 **回归打底 + 扩散精修**，不要从零训 DDPM。

## 已知限制

1. **GT 质量不均**：`output` 由自动化流程生成，已发现混入卡通插画、近空白页等语义异常样本；
   清洗能剔除一部分，但会残留。这会拉低指标上限。
2. **无像素级 mask 标注**：使用代理掩码，依赖"手写是输入与 GT 的主要差异"这一假设，
   在"手写与印刷体颜色接近"的区域会失效。
3. **黑色手写压在黑色印刷体上**是最难的情形，当前结构只能给出折中的灰色结果。
4. **训练与推理都在 `1/2` 缩放分辨率下进行**（`--downscale 2`），
   原尺寸下小于 ~2 px 的细笔画可能丢失。
5. 少数配对存在真实的几何/版式不一致（GT 与输入并非严格同页），
   这类样本会迫使网络学"重排版式"，属于噪声监督。
